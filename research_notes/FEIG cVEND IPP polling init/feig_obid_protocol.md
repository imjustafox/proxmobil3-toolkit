# FEIG OBID / cVEND Serial Protocol: Reader Init & ISO14443 Polling

> Scope note: FEIG runs two parallel product/protocol worlds. (1) The **OBID / ID ISC classic-pro / i-scan** RFID readers use a fully, publicly documented serial "Reader Protocol" (ASCII/binary frames, command bytes like 0x69, 0xB0, 0x0B). (2) The **cVEND payment terminals** ("cVEND plug", "plug flex", "compact II") are a separate secure-payment product line whose host/application interface (the certificate handshake, INITIALIZED state, `feclr`-style API) is distributed **only under NDA/on request** and is **not public**. Claims below are marked **[FEIG-generic]** (OBID reader protocol, applies to the RF front-end that cVEND is built on) or **[cVEND-specific]** (payment terminal app layer). Where cVEND-specific internals could not be confirmed from public sources, they are logged as Gaps.

---

## Key Question 1 — OBID protocol family + standard commands (RF on/off, operating modes, Inventory, config)

### Takeaway
FEIG's OBID readers speak the documented "FEIG Reader Protocol" (a.k.a. OBID classic-pro / ID ISC "Advanced Protocol" and "Standard Protocol" frame formats). Core host commands are identified by a single **control/command byte**: RF Reset `0x69`, ISO15693 host-command group `0xB0` (sub-command `0x01` = Inventory), newer unified "ISO Standard Host Command" `0x0B` (sub-command `0x01` = Inventory across ISO14443A/B/15693), plus a configuration block (`0x80`–`0x83`) and read-mode protocols (Buffered Read Mode / Notification Mode). [FEIG-generic]

### Cited Findings
- FEIG ships two frame formats: **Standard Protocol** and **Advanced Protocol** (`FeigProtocol.Standard` / `FeigProtocol.Advanced` in the open-source C# driver that re-implements the FEIG protocol). A request carries `Address` (bus address / COM-ADR), `Command`, and `Data`; a response carries `Status` and `Data`; transfer status includes `Success`, `Timeout`, `Canceled`, `ChecksumError`, and reader status `FeigStatus.OK` — [Amarok79/InlayTester.Drivers.FeigReader (GitHub)](https://github.com/Amarok79/InlayTester.Drivers.FeigReader)
- Command bytes documented by that C# driver (each is the protocol control byte): **`0x52` Baud Rate Detection** (`TestCommunication()`), **`0x63` CPU Reset** (`ResetCPU()`), **`0x65` Get Software Version/Info** (`GetSoftwareInfo()`), **`0x69` RF Reset** (`ResetRF()`), **`0x80` Read Configuration**, **`0x81` Write Configuration**, **`0x82` Save Configuration**, **`0x83` Set Default Configuration**, and **`0x0B 0x01` Inventory (ISO Standard Host Command)** — [Amarok79/InlayTester.Drivers.FeigReader (GitHub)](https://github.com/Amarok79/InlayTester.Drivers.FeigReader)
- The FEISC function library defines **`FEISC_RF_RESET = 0x69`** and **`FEISC_ISO_COMMAND = 0xB0`**, with a C function prototype **`FEISC_0x69_RFReset(int iReaderHnd, unsigned char cBusAdr)`** — from the ROS `rfid_drivers` doxygen for FEIG's `feisc.h` (search-extracted; page itself is behind a bot-wall) — [docs.ros.org feisc.h (FEISC)](https://docs.ros.org/en/hydro/api/rfid_drivers/html/feisc_8h.html)
- The **`0xB0` group is "Host Commands for ISO15693"**, and within it **`[0x01]` is Inventory** (mandatory command). The OBID i-scan ID ISC.PR101/MR101 manual lists "[0xB0] Host commands for ISO15693 Mandatory and Optional Commands" with "[0x01] Inventory", and lists "[0x69] RF Reset" as a separate section — [Feig OBID i-scan ID ISC.PR101/MR101/PRH101 User Manual (manualmachine)](https://manualmachine.com/feigelectronic/obidiscanidiscmr101/23026941-user-manual)
- Pepperl+Fuchs (an OBID OEM reseller) documents the same: "[0xB0] Host commands" with "[0x01] Inventory" as the first sub-command — [Pepperl+Fuchs OBID manual tdoct8610 (PDF)](https://files.pepperl-fuchs.com/webcat/navi/productInfo/doct/tdoct8610__eng.pdf)
- The classic-pro CPR30.xx manual groups other command sets by protocol, e.g. **`[0xBE]` ISO14443B Transparent Command** and **`[0xC0]` SAM Commands**, confirming command bytes are organized per card standard — [Feig OBID classic-pro Series Manual (manualslib)](https://manualslib.com/manual/1633605/Feig-Electronic-Obid-Classic-Pro-Series.html)
- The FEDM C++ layer exposes Host-Mode inventory results keyed by command **`[0xB0][0x01] Inventory`** via `FEDM_ISOTabItem` (the per-tag table item holding UID etc.) — [docs.ros.org FEDM_ISOTabItem class (search-extracted)](https://docs.ros.org/en/hydro/api/rfid_drivers/html/classFEDM__ISOTabItem.html)
- **Operating modes**: OBID readers support **Host Mode**, **Scan Mode**, **Buffered Read Mode (BRM)**, and **Notification Mode**, selected by configuration bits. Per the ID ISC.LR1002 manual: BRM is only available if Scan Mode is disabled; **Notification Mode is enabled by a config bit and works only together with BRM** — [Feig OBID ID ISC.LR1002 Manual (manualslib)](https://manualslib.com/manual/1732092/Feig-Electronic-Obid-Id-Isc-Lr1002.html)
- In BRM/Notification Mode the host retrieves collected tags with **`[0x22] Read Buffer`** (listed in FEIG-family "Protocols for Buffered Read Mode and Notification Mode") — [RF-R400 System Manual (Scribd, FEIG-family protocol)](https://www.scribd.com/document/550696239/RF-R400-System-Manual)
- Inventory can be configured to **stop once the UIDs of all ISO14443A or all ISO14443B transponders in range have been read** (an Inventory-abort config parameter), per the CPR70 manual — [FEIG CPR70 Manual (Scribd)](https://www.scribd.com/document/721525509/FEIG-CPR70-Manual)
- FEIG's official SDK datasheet confirms the two API families: a **Reader Control API** and an **"Auto Read Mode" API for getting collected data from a reader working in Buffered Read Mode or Notification Mode** — [FEIG Software Development Kit GEN3 datasheet (PDF)](https://feig.de/wp-content/uploads/Data_sheet_Software_Development_Kit_GEN3.pdf)

### Inferences
- There are **two Inventory encodings** in the FEIG world and the correct one depends on reader firmware/command set: the **classic per-standard group** (`0xB0 0x01` = ISO15693 Inventory; an analogous ISO14443 host-command group exists in the same byte range, e.g. around `0xB2`/`0xBE`) **vs.** the **unified "ISO Standard Host Command" `0x0B` with sub-command `0x01`** that selects the air standard (ISO14443A/B/15693) via a mode byte in the payload. For a modern reader, `0x0B 0x01` is the single call that returns ISO14443 UIDs; on older firmware you use the per-standard group. (Derived from the `0xB0 0x01` vs `0x0B 0x01` conflict across the i-scan manual and the C# driver.)
- The control byte in these findings is the FEIG "command/control byte"; a full frame additionally wraps it with STX/length, COM-ADR (bus address), status byte, and CRC16 (the C# driver's `ChecksumError` status implies a checksum, though the exact CRC16 polynomial was not captured here).

### Gaps
- Exact byte-level frame layout (STX `0x02` marker, 2-byte length, COM-ADR, control byte, LEN/DATA, 1-byte status, CRC16-CCITT poly/seed) was not captured from a primary FEIG manual in this pass — the authoritative frame tables live in the FEIG "ID ISC... System Manual / Reader Protocol" PDFs and in `feisc.h`, both of which were bot-walled (docs.ros.org Anubis) or not opened in full.
- **RF Output ON/OFF as a dedicated command** (sometimes cited as `0x6A`) was not confirmed from any source here; public OBID docs expose RF antenna power control via **`0x69` RF Reset** and via **configuration (`0x80`/`0x81`, RF-power config block)** rather than a simple on/off opcode. Treat `0x6A` as unverified.

## Key Question 2 — Does cVEND use a transparent/application layer on OBID? The startup certificate handshake / INITIALIZED state, and public docs

### Takeaway
cVEND is a **secure payment terminal**, not a bare OBID reader: it exposes a FEIG-proprietary secure host protocol with a **"payment mode" and a "transparent card reader mode"**, and its startup performs a **device-certificate / secure-session** step before it will read cards. This application layer (including the certificate validity report and INITIALIZED transition) is **documented only in NDA cVEND SDK/integration material available "on request"**, and was **not found in any public source**. [cVEND-specific]

### Cited Findings
- The FEIG cVEND user manual states the cVEND reader "offers an easy to use secure protocol" and "can be used in **payment mode as well as in transparent card reader mode**" — confirming a transparent (raw-card) mode layered on top of the secure payment stack. Support is gated behind `cvend-support@feig.de` (technical) / `cvend@feig.de` (commercial) — [Feig cVEND User Manual (manualmachine, snippet via search)](https://manualmachine.com/feigelectronic/cvend/11347140-users-manual)
- cVEND terminals carry **manufacturer-issued X.509 device certificates used for key encryption and device authentication** (third-party terminal-registration API describing FEIG terminals) — [SFEY TPS Device API, Key Management (sfeydocs)](https://sfeydocs.sfey.com/docs/doc-api-spec/API%20v3.0/TPS%20Device%20API/Terminal%20Registration/03%20Key%20Management%20Automatic)
- cVEND compact II platform supports, at the card layer: **ISO/IEC 14443-A / -B and ISO/IEC 15693**, with card detection for **MIFARE, Calypso, Sony FeliCa**, and **NFC devices in card-emulation mode**; it is a "secure device designed for local or remote application and key loading" with L2 customization — [FEIG cVEND compact II "Platform for App Development" datasheet (PDF)](https://www.feig.de/wp-content/uploads/FEIG_Data-sheet-cVEND-compact-II-Platform-for-App-Development.pdf)
- cVEND host/physical interfaces include **RS232, USB 2.0 OTG, Ethernet** (plus LTE on compact II) — i.e. the "serial/UART host interface" in scope is the RS232/USB-CDC link — [FEIG cVEND compact II datasheet (PDF)](https://www.feig.de/wp-content/uploads/FEIG_Data-sheet-cVEND-compact-II-Platform-for-App-Development.pdf)
- cVEND datasheets (plug flex / NMI) state **"Development devices, tools and SDK available on request"** — i.e. the protocol/SDK is distributed privately, not downloadable — [cVEND plug flex datasheet (PDF)](https://feig.de/wp-content/uploads/Data_sheet_cVEND_plug_flex_EN.pdf); [cVEND plug NMI datasheet (PDF)](https://feig.de/wp-content/uploads/Data_sheet_cVEND_plug_NMI_EN.pdf)
- cVEND runs a renewable payment **"kernel"** (EMV L2) that FEIG updates in the field, indicating a firmware/application layer distinct from the raw RFID front-end — [FEIG "cVEND kernel renewal is complete" (PDF)](https://www.FEIG.de/fileadmin/user_upload/Downloads/News/2022-06-15_cVEND_kernel_renewal_is_complete_en.pdf)

### Inferences
- The observed boot behavior ("device certificates valid until <date>" → INITIALIZED state before card reads) is consistent with a **PCI/EMV secure-boot + device-attestation handshake**: the terminal validates its X.509 device/key certificates at power-up, loads/unlocks the secure app and keys, and only then enables the contactless field and card polling. This matches the X.509 device-certificate and local/remote key-loading design FEIG documents, but the specific log string and the INITIALIZED state machine are cVEND firmware internals not published publicly.
- "Transparent card reader mode" is the path to a **raw ISO14443 UID without payment authentication** on cVEND — the secure/payment protocol wraps the same OBID RF front-end, and transparent mode exposes near-raw reader behavior once the terminal has reached INITIALIZED.

### Gaps
- No public document describes the cVEND **startup certificate handshake byte sequence**, the **"device certificates valid until" report**, or the **INITIALIZED state transition**. These are in the NDA cVEND SDK / "FEIG Service Interface" documentation only. Obtain via `cvend-support@feig.de` or the on-request SDK.
- Whether transparent mode is reachable **before** certificate validation completes, or only after INITIALIZED, is unconfirmed (inference says after).

## Key Question 3 — SDK API that enables polling and returns a RAW ISO14443 UID pre-authentication (`feclr_*`, `feisc_*`, FEDM)

### Takeaway
Two distinct SDK stacks exist. For **OBID readers**, the public FEIG SDK stack is **FEISC (C function library) → FEDM (C++ class library) → FETCP/FECOM transport**, and `FEISC_0x0B`/`0xB0` Inventory + `FEDM_ISOTabItem` give the raw UID with no application keys. For **cVEND**, FEIG uses a separate contactless-reader library (the `feclr`-style "FEIG Contactless Reader" API); its function names and the "get UID in transparent mode" call are **NDA-only and were not found publicly**. [FEIG-generic for FEISC/FEDM; cVEND-specific for feclr]

### Cited Findings
- **FEISC / FEDM layering**: FEISC is a function library (DLL/SO) and FEDM is the C++ class library built on top (FEDM Core / CoreAPI alongside FEISC and FETCP). FEDM's `FEDM_ISCReaderModule` drives readers; changelog references `FEISC_TASKID_FIRST_NEW_TAG` (continuous/async inventory task) and `TagInventory` with TagHandler support for up to **10-byte UIDs** (covers 4/7/10-byte ISO14443A UIDs) — [docs.ros.org FEDM_ISCReaderModule.cpp (search-extracted)](https://docs.ros.org/en/hydro/api/rfid_drivers/html/FEDM__ISCReaderModule_8cpp_source.html)
- **Raw UID, pre-auth**: the **`[0xB0][0x01]` / `0x0B 0x01` Inventory** command performs ISO anticollision and returns the transponder serial number (UID) itself — no MIFARE/application key is needed for Inventory; keys are only required for subsequent block Read/Write/Authenticate. `FEDM_ISOTabItem` is the result record that holds each tag's UID from a Host-Mode `[0xB0][0x01]` inventory — [docs.ros.org FEDM_ISOTabItem (search-extracted)](https://docs.ros.org/en/hydro/api/rfid_drivers/html/classFEDM__ISOTabItem.html); [Amarok79/InlayTester.Drivers.FeigReader `Inventory()` returns ISO14443A/B tag IDs](https://github.com/Amarok79/InlayTester.Drivers.FeigReader)
- FEIG's official SDK (GEN3) provides a **common API across C++, C#, Java**, with a **Reader Control API** (direct commands incl. Inventory) and an **Auto Read Mode API** (BRM/Notification collection) — [FEIG SDK GEN3 datasheet (PDF)](https://feig.de/wp-content/uploads/Data_sheet_Software_Development_Kit_GEN3.pdf)
- Open-source re-implementations confirm raw-UID polling over serial without keys: the C# `IFeigReader.Inventory()` returns tag IDs for ISO14443A/B & ISO15693; a Node.js driver's `reader.inventory()` returns `{status, raw, tags}` with tag IDs (tested on ID CPR40.xx / CPR74.xx over USB VID 0x0AB1/2737) — [Amarok79/InlayTester.Drivers.FeigReader](https://github.com/Amarok79/InlayTester.Drivers.FeigReader); [joostkamphuisnl/feig-driver README](https://worker-github.zxx930427.workers.dev/joostkamphuisnl/feig-driver)

### Inferences
- To get a **raw ISO14443 UID** from an OBID/cVEND RF front-end pre-auth, the minimal host sequence is: (optionally) `0x52` Baud Rate Detection to sync → `0x65` Get Software Info → `0x69` RF Reset (energize/reset field) → `0x0B 0x01` (or `0xB0 0x01`) Inventory → parse `FEDM_ISOTabItem` / response Data for the UID. No keys involved. For continuous detection use BRM/Notification Mode + `0x22` Read Buffer or the Auto Read Mode API (`FEISC_TASKID_FIRST_NEW_TAG`).
- `feclr` is almost certainly FEIG's **"FEIG Contactless Reader"** C library specific to the cVEND/transit payment stack (parallel to FEISC for OBID). Its existence is implied by FEIG's architecture but could not be sourced; the raw-UID call in cVEND transparent mode is the `feclr` analog of `FEISC ... Inventory`.

### Gaps
- No public source names any `feclr_*` function (e.g. a hypothetical `feclr_startCardPolling` / `feclr_getCardInfo`). `feclr` / `libfecom` returned **zero** public hits. These are NDA cVEND SDK symbols — confirm via FEIG.
- Exact FEISC/FEDM function spelling for one-shot inventory (e.g. `FEISC_0x0B_ISOCmd` vs `FEISC_0xB0_ISOCmd`) and the `FEDM` method (`FEDM_ISCReader::sendProtocol(0xB0)` / `::inventory()`) was not captured verbatim (doxygen pages bot-walled).

## Key Question 4 — Command codes: enable card type, start/stop polling, LED, buzzer, card-detected notifications

### Takeaway
On OBID readers these are mostly **configuration-register writes + Inventory/mode commands**, not one-off opcodes: card types are enabled in a configuration block (`0x80`/`0x81`), polling is "start" = entering BRM/Scan/Notification mode or issuing `0x0B/0xB0 Inventory` and "stop" = RF Reset / mode change, and LED/buzzer are driven through output/notification config. cVEND exposes payment-terminal LED/buzzer/card-detect through its secure app protocol, which is NDA. [mixed]

### Cited Findings
- **Enable card type**: done via the **Read/Write Configuration** block — `0x80` Read Configuration, `0x81` Write Configuration, `0x82` Save Configuration, `0x83` Set Default Configuration; the config parameters select which transponder drivers/standards (ISO14443A/B, ISO15693, etc.) are active — [Amarok79/InlayTester.Drivers.FeigReader](https://github.com/Amarok79/InlayTester.Drivers.FeigReader); FEIG config parameter controlling ISO14443A/B inventory behavior documented in [FEIG CPR70 Manual (Scribd)](https://www.scribd.com/document/721525509/FEIG-CPR70-Manual)
- **Start/stop polling**: "start" = issue **`0x0B 0x01` / `0xB0 0x01` Inventory** (single scan) or enable **Buffered Read / Scan / Notification Mode** via config; the reader then auto-polls and the host reads tags with **`0x22` Read Buffer**. Mode bits (Host/Scan/BRM/Notification) are mutually constrained (BRM needs Scan off; Notification needs BRM on) — [Feig OBID ID ISC.LR1002 Manual](https://manualslib.com/manual/1732092/Feig-Electronic-Obid-Id-Isc-Lr1002.html); [RF-R400 System Manual, `[0x22] Read Buffer`](https://www.scribd.com/document/550696239/RF-R400-System-Manual)
- **Card-detected notification**: in **Notification Mode** the reader asynchronously pushes a Notification frame when a new tag enters the field (works only with BRM); FEIG's SDK "Auto Read Mode API" and the `FEISC_TASKID_FIRST_NEW_TAG` task deliver these new-tag events to the host — [FEIG SDK GEN3 datasheet (PDF)](https://feig.de/wp-content/uploads/Data_sheet_Software_Development_Kit_GEN3.pdf); [docs.ros.org FEDM_ISCReaderModule.cpp (FEISC_TASKID_FIRST_NEW_TAG)](https://docs.ros.org/en/hydro/api/rfid_drivers/html/FEDM__ISCReaderModule_8cpp_source.html)
- **RF reset / field control**: `0x69` RF Reset resets/re-energizes the RF field (effectively stop+restart polling) — [Amarok79/InlayTester.Drivers.FeigReader](https://github.com/Amarok79/InlayTester.Drivers.FeigReader); [feisc.h FEISC_RF_RESET=0x69 (search-extracted)](https://docs.ros.org/en/hydro/api/rfid_drivers/html/feisc_8h.html)

### Inferences
- There is **no single "enable card type" or "start polling" opcode** on classic OBID; integration is: write config (card drivers + mode) → save → RF reset → Inventory/BRM. This is the FEIG-generic pattern cVEND inherits at the RF layer.
- **LED and buzzer**: OBID readers that have them drive them through **output/notification configuration parameters** (and some readers expose an output-port/"Set Output" command), not a universally-named opcode. On cVEND, LED/buzzer are part of the **payment-terminal UI** controlled by the secure app protocol (display/LED/beep commands), which is cVEND-specific.

### Gaps
- No public source gave a dedicated **LED-control** or **buzzer-control** command opcode for OBID or for cVEND. (OBID uses config/output parameters; cVEND uses its NDA app protocol. A FEIG "Set Output" / port-control command exists on some readers but was not pinned to a hex code here.)
- The **cVEND-specific** "enable card reading / start poll / card-present event" commands and the LED/buzzer opcodes in the secure payment protocol are **not public** — only in the NDA cVEND SDK / FEIG Service Interface spec.

## Cross-cutting source-quality notes
- The **most authoritative primary sources** (FEIG "ID ISC... System Manual", the `feisc.h`/`fedm` headers, and the cVEND SDK) were partially inaccessible: docs.ros.org (which mirrors FEIG's `rfid_drivers`/FEDM doxygen) is behind an **Anubis bot-wall**, and the cVEND SDK is **NDA/on-request**. Command-code facts here are corroborated across **(a)** FEIG OEM manuals (i-scan, classic-pro, CPR70, LR1002 via manualslib/manualmachine/scribd), **(b)** FEIG's own SDK datasheet, and **(c)** independent open-source re-implementations (Amarok79 C#, joostkamphuisnl Node) — convergence is good for `0x69`, `0x52`, `0x63`, `0x65`, `0x80-0x83`, `0xB0 0x01`, `0x0B 0x01`, `0x22`.
- **Known conflict (flagged, not silently resolved)**: Inventory is cited as **`0xB0 0x01`** (ISO15693 host-command group, FEIG i-scan/Pepperl+Fuchs manuals) and as **`0x0B 0x01`** (ISO Standard Host Command, Amarok79 C# driver). These are two different-but-real command encodings in FEIG firmware generations; for ISO14443 UID on modern firmware prefer `0x0B 0x01` with the air-standard selected in the payload.
